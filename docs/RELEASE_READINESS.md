# Phase 8 릴리스 준비 · Windows 회귀 점검

이 문서는 출시 승인 기록이 아닌 점검 절차입니다. 자동 검증과 실제 Windows UI 검증을 모두 통과한 뒤 배포 여부를 결정합니다. 취소와 백분율 진행률은 백엔드·UI 어디에서도 제공하지 않습니다.

## 실행 환경과 개인정보

- 사용자 실행: Windows 10/11 및 Microsoft Edge WebView2 Runtime. 문서 PDF 변환만 별도 로컬 LibreOffice와 호환 가져오기 필터가 필요합니다. 앱이 런타임이나 LibreOffice를 자동 설치하지 않습니다.
- 개발/컴파일: Node.js/npm, Rust stable/Cargo, Microsoft C++ Build Tools와 Windows SDK. 버전은 package-lock.json과 src-tauri/Cargo.lock을 함께 보관합니다. PowerShell 정책이 npm.ps1을 막으면 npm.cmd를 사용합니다.
- 이미지/PDF/Excel 및 개인정보 검사는 로컬에서 처리합니다. 문서 변환은 로컬 LibreOffice 프로세스에 입력 경로를 전달합니다. 파일 본문을 서버로 업로드하는 기능이나 원격 분석은 없습니다. 개발용 Vite 서버는 루프백 주소를 사용합니다.
- 개인정보 검사 결과는 마스킹하지만 워크플로 기록에는 입력/출력 전체 경로, 템플릿 이름과 오류가 남습니다. 파일명에도 개인정보가 있을 수 있습니다. 출력 문서는 자동 마스킹되지 않습니다.
- 저장 위치: `%LOCALAPPDATA%\kr.eduwork.tools\workflows.json` (Tauri app_local_data_dir). 템플릿 100개, 최신 기록 200개, JSON 8 MiB 제한입니다. 손상·초과 JSON은 자동 초기화하지 않습니다.
- 백업: 작업 완료 후 앱을 정상 종료하고 workflows.json과 필요한 출력 문서를 별도 안전한 위치에 복사합니다. 복원: 앱을 종료한 상태에서 현재 JSON도 따로 백업한 뒤 정상 백업본으로 교체하고 재시작합니다. JSON은 문서 자체를 포함하지 않으며 원래 경로가 바뀌면 실행할 때 경로를 다시 선택해야 합니다.

## 정확성 보장과 제한

이미지/PDF/XLSX 워크플로는 같은 출력 폴더의 임시 파일에 완성·동기화한 뒤 덮어쓰기 없는 원자적 게시를 사용합니다. 동시 출력 충돌 시 기존 파일을 보존하며 이미지는 번호 이름을 다시 시도합니다. 여러 출력 전체를 하나의 트랜잭션으로 처리하지는 않습니다. 실패 기록의 완료된 출력 목록을 확인하고 재실행 위치를 선택하세요. 강제 종료 후에는 시작 기록만 남을 수 있으며 출력 폴더와 임시 파일을 직접 확인해야 합니다. 강제 종료 중 임시 파일 자동 복구는 지원하지 않습니다.

폴더/링크 검증 후 외부 프로그램이 디렉터리를 교체하는 공격에 대한 OS 파일 핸들 기반 격리는 없습니다. 신뢰하는 로컬 폴더에서 사용하세요. 여러 앱 프로세스가 같은 workflows.json을 동시에 편집하는 것은 지원하지 않습니다. 출력 충돌 방지는 프로세스 간에도 적용되지만 기록 병합은 제공하지 않습니다.

미지원: 취소, 백분율 진행률, 예약 실행, 임의 단계 편집, 자동 중단 복구, 다중 시트 자동 명단 정리, HWPX PDF 변환, OCR, 완전한 개인정보 감사. HWP 호환성은 LibreOffice 필터와 문서에 따라 다릅니다. Excel은 문자열 값 처리이며 원래 수식·서식을 보존하지 않습니다.

## 수동 Windows 회귀 절차

테스트용 복사본만 사용하고 시작 전 원본 해시와 기존 출력 내용을 기록합니다. 기존 앱/개발 서버를 종료하거나 강제 중단하지 않습니다. 포트/실행 파일 잠금으로 새 빌드가 막히면 차단 상태를 기록하고 기존 앱과 새 소스의 검증 결과를 구분합니다.

1. `npm.cmd run tauri:dev`로 네이티브 창을 열고 모든 메뉴·파일 선택 대화상자·한글 파일명·한글 오류를 확인합니다. UI만의 Vite 실행은 네이티브 검증으로 간주하지 않습니다.
2. 파일 관리: 이름 변경 미리보기/충돌 거부/적용, 중복 검사, 검색, CSV/XLSX 내보내기. 원본과 예상 결과를 비교합니다.
3. 이미지: JPG/PNG/WebP, 비율 유지/정확한 크기/여백/품질. 깨진 이미지와 정상 이미지를 섞어 오류 후 계속 처리 및 기존 출력 보존을 확인합니다.
4. PDF: 병합 순서, 범위 추출, 분할, 이미지 PDF. 손상/암호화/잘못된 범위/출력 충돌 오류와 원본 보존을 확인합니다.
5. Excel: 병합/분할/정리/CSV/명단. 한국어, 빈 행, 중복, 숫자 정렬, 머리글 불일치 및 그룹 출력 충돌을 확인합니다.
6. 문서 변환: LibreOffice 없음 오류와 설치된 환경의 DOCX/XLSX/PPTX PDF 변환을 각각 확인합니다. HWP 제한과 HWPX 거부를 확인합니다. 개인정보 검사에서 정상·손상 파일 혼합, 마스킹 및 BOM CSV를 확인합니다. 스캔 PDF는 OCR되지 않음을 확인합니다.
7. 업무 자동화: 이미지/PDF/XLSX 예제를 각각 실행합니다. 템플릿 저장→재시작→불러오기→같은 이름 갱신→삭제를 확인합니다. 잘못된 입력/출력 종류와 충돌이 원본을 바꾸지 않는지, 실패 및 일부 완료 목록이 재시작 후에도 남는지 확인합니다. 201회 유지 정책은 자동 테스트로 검증합니다.
8. 취소 버튼이나 가짜 진행률이 없는지 확인합니다. 장시간 작업 중 화면 응답과 중복 실행 방지를 확인합니다. 작업 종료 후 백업/복원을 수행하고 기록을 다시 읽습니다. 손상 JSON 복사본으로 오류 표시와 원문 보존을 확인한 뒤 백업으로 복원합니다.

- 업무 자동화 Excel UI 회귀를 완료했습니다. `qa-roster.xlsx`, `qa-roster-2.xlsx` 2개를 합친 결과는 ZIP 무결성·`Roster` 시트·머리글 `Name, Score`·한국어 학생 3행을 통과했고, 실행 전후 입력 SHA-256이 같았습니다. 그룹 열 2 설정으로 다시 실행해 전체 결과와 `group-001`(점수 10), `group-002`(점수 9) 파일 3개를 확인했으며 모두 ZIP 무결성이 정상이고 입력 해시는 유지됐습니다. 시험 산출물은 `%LOCALAPPDATA%\hermes\cache\scratch\qa-excel-workflow-output.xlsx` 및 `qa-excel-grouped*.xlsx`입니다.
- 시험 종료 후 `%LOCALAPPDATA%\kr.eduwork.tools\workflows.json`을 시험 전 백업과 바이트 단위로 복원하고 UI에서 다시 읽었습니다. 시험용 템플릿은 남지 않았고 기존 이미지 워크플로 기록 1건이 유지됐습니다.
- 별도 Cargo target으로 Windows 실행 파일·NSIS·MSI 산출물을 만들고 `release-artifacts/v0.1.0/`에 복사했습니다. 실행 파일을 직접 열어 한국어 UI 렌더링을 확인했고, Authenticode 검사 결과 세 산출물 모두 `NotSigned`입니다.
- NSIS 설치 파일은 scratch에 무인 설치·앱 실행·UI 렌더링·제거까지 확인했습니다. 제거 후 설치 폴더와 Uninstall 항목이 남지 않았고 `%LOCALAPPDATA%\kr.eduwork.tools\workflows.json`의 내용도 시험 전과 동일했습니다.
- MSI 파일 형식 헤더와 admin image 추출을 확인했고 추출된 앱의 UI도 렌더링됐습니다. 일반 `/i` 설치는 종료 코드 1603, 로그의 Error 1925(모든 사용자 설치에 관리자 권한 필요)로 실패했습니다. 권한 상승은 하지 않았으므로 MSI의 실제 설치·제거는 미검증입니다.
- 초기 로컬 검증 당시 Git remote가 없었고 프로젝트 파일은 미추적 상태였습니다. 이후 사용자가 공개 저장소 생성을 승인해 `invinciblebearme-ctrl/eduwork-tools`의 `main`에 소스 커밋을 게시하고 v0.1.0 Release를 공개했습니다. 설치 파일·실행 파일·안내·SHA-256 manifest 총 5개 자산을 다시 내려받아 원격 바이너리의 크기와 SHA-256을 로컬 manifest와 대조했습니다.
- 릴리스 게이트는 아직 모두 통과하지 않았습니다: 코드 서명, 라이선스 지정, MSI 관리자 설치 검증이 남았습니다. LibreOffice 기반 문서 변환 UI 경로도 환경에 LibreOffice가 없어 미검증입니다.
